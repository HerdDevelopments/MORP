Modding Open
Resource Protocol

MORP is a platform-agnostic scripting abstraction for GTA V multiplayer modding. Write resources once against the MORP spec — deploy on any compliant platform.

What is MORP? #what

A portability and standardization layer for GTA V multiplayer scripting.

The GTA V modding ecosystem has a fragility problem. Platforms rise and die — when a platform gets shut down or abandoned, server owners lose years of work because everything was written against that platform's specific API.

MORP is an abstraction layer. Your scripts talk to MORP's unified API. MORP adapters translate those calls to whatever the underlying platform needs. When a new platform ships a MORP adapter, your resources work there immediately.

// Get Started

Quick Start

From zero to a running MORP resource in under 2 minutes.

Prerequisites

Requirements
Node.js 18 or higher. A FiveM server for live testing (optional for CLI steps).
1
Install the CLI
bash
npm install -g morp-cli
2
Scaffold a resource
bash
morp init my-resource
cd my-resource
3
Add the adapter to your FiveM manifest
luafxmanifest.lua
fx_version 'cerulean'
game 'gta5'

-- MORP Protocol 0.2
shared_script '@morp-core/adapter/lua/morp_adapter.lua'

server_script 'server.lua'
client_script 'client.lua'
4
Write your first handler
luaserver.lua
MORP.on('playerConnect', function()
  local src  = source
  local name = MORP.player.getName(src)
  MORP.log.info('Connected: ' .. name)
  MORP.state.player(src).set('job', 'civilian')
end)
5
Validate and run
bash
morp validate
morp dev  # hot reload watcher

Event Bus

MORP's unified event system. Local events, network events, and lifecycle hooks — all through one consistent API.

Lifecycle Events

EventSideDescription
startbothResource has started
stopbothResource is stopping
playerConnectserverPlayer is connecting (deferrals available)
playerDisconnectserverPlayer has disconnected. source is available
playerSpawnbothPlayer spawned into world
clientReadyclientClient-side scripts fully loaded

Network Events

FunctionSideDescription
MORP.on(event, fn)bothListen to an event
MORP.off(event, fn)bothRemove an event listener
MORP.emit(event, ...)bothTrigger a local event
MORP.emitServer(event, ...)clientSend event to server
MORP.emitClient(player, event, ...)serverSend event to specific client
MORP.emitAllClients(event, ...)serverBroadcast to all clients
MORP.emitAllClientsExcept(player, event, ...)serverBroadcast excluding one player
luaexample
-- Server: listen and respond
MORP.on('myres:requestData', function()
  local src = source
  MORP.emitClient(src, 'myres:data', { score = 100 })
end)

-- Client: request then handle
MORP.on('clientReady', function()
  MORP.emitServer('myres:requestData')
end)

MORP.on('myres:data', function(data)
  MORP.log.info('Score: ' .. data.score)
end)

Vehicle API

Spawn, modify, and query vehicles. Extends the base Entity API.

Spawning

Client-side only
Vehicle spawning is client-side. Notify the server via MORP.emitServer with the network ID for server-side tracking.
luaclient.lua
local hash   = GetHashKey('sultan')
local coords = MORP.player.getCoords()

MORP.entity.loadModel(hash, function()
  local veh = MORP.vehicle.spawn(hash, coords, 0.0, {
    plate    = 'MORP01',
    color    = { primary = 27, secondary = 0 },
    fuel     = 100.0,
    engineOn = false,
  })

  MORP.vehicle.setNeonEnabled(veh, true, true, false, false)
  MORP.vehicle.setNeonColor(veh, 0, 255, 128)
end)

Resource Signing

Ed25519 cryptographic signing for MORP resources. Tamper detection and publisher verification.

How it works

Algorithm
Ed25519 (RFC 8032) — the same algorithm used by SSH, WireGuard, and Signal.

Signing creates a cryptographic proof that a resource came from you and hasn't been modified. The adapter can verify this on load.

Full workflow

bash
# 1. Generate keypair (do this once)
morp keygen keys/

# 2. Hash all files
morp build

# 3. Sign with your private key
morp sign --key keys/morp_private.pem

# 4. Verify (test before distributing)
morp verify --key keys/morp_public.pem
Security
Never commit morp_private.pem to version control. Add it to .gitignore. Loss of the private key means you cannot sign future updates under the same identity.
Tooling › Dev Server

Dev Server

Hot reload watcher with SSE for live change detection during development.

Usage

bash
cd my-resource
morp dev               # default port 7700
morp dev . --port=8080 # custom port

SSE Events

Connect to http://localhost:7700/events to receive file change notifications as Server-Sent Events.

jsFiveM NUI or browser
const es = new EventSource('http://localhost:7700/events')
es.onmessage = (e) => {
  const data = JSON.parse(e.data)
  console.log('Changed:', data.file, data.ts)
}

Status endpoint

GET http://localhost:7700/status returns current watch state as JSON.

Exports / Imports

Cross-resource function sharing.

lua
-- Declare an export
MORP.export('getJob', function(src)
  return MORP.state.player(src).get('job')
end)

-- Consume from another resource
local getJob = MORP.import('jobs', 'getJob')
local job = getJob(src)

Callbacks

Async request/response between server and client.

lua
-- Server: register
MORP.callback.register('myres:getData', function(src, cb, arg)
  cb({ value = arg * 2 })
end)

-- Client: trigger
MORP.callback.trigger('myres:getData', function(data)
  MORP.log.info(data.value)
end, 21)
